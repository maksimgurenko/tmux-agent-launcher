# Installing with an agent

Use this guide from the same selected revision as the code/installer. Record the checkout's origin and revision locally. Respect a user-selected fork (`scripts/install.sh --repo OWNER/REPO`); never fetch moving-branch instructions separately from a selected release.

1. Read applicable local instructions and inspect Linux, tmux (`3.7c+`), selected picker/terminal, PATH, XDG directories and installed agent executables. Inspect only host configuration needed for this integration. Detect symlinks, Stow/package managers and any existing launcher ownership records. Keep machine values and credentials local.
2. Use defaults when suitable. Infer installed backends; resolve only missing preferences or authorization for dependencies/configuration changes. The installer manages no system packages or agent CLIs. Do not ask for secrets in issues or commits. Permission-bypassing preset behavior is documented in README; customize argv when requested.
3. Explain actual files: `PREFIX/bin/tmux-agent-launcher`, LICENSE/NOTICE and ownership/rollback records in the data directory; optional private TOML; optional narrow desktop bindings/rules. The launcher creates cache locks and short-lived private environment snapshots. User-level installation needs no privileges or services. Respect already-granted authorization; stop on unmanaged file conflicts rather than overwrite.
4. Run the maintained `scripts/install.sh` with an exact trusted version/repository, or `--archive FILE --checksum DIGEST` for a verified local artifact. For source, run `scripts/build.sh` / `scripts/release.sh` and install its archive. Never take ownership of a Stow-managed file silently. Preserve config; back up before requested edits. Merge only selected keys and unused hotkeys/rules. Use the example matching the host's Hyprland Lua version; reload only after checking syntax.
5. Run `--version` and `doctor`. Expected: version/source identity; compatible tmux; selected dependencies present. Uninstalled optional agent profiles are informational. Test selection/cancellation and create/reuse a disposable profile running `sleep` with a disposable tmux socket, or a user-approved real profile. Check actual terminal class and float/tile placement, and attachment in a fresh window. File installation alone does not establish desktop success. Report missing graphical access or untested backends/native ARM64 explicitly.
6. Report revision, source/binary digest, installed paths, config/integration changes, backups and observed checks. Roll back with this revision's `scripts/install.sh --rollback`; uninstall with `--uninstall`, repeating prefix/data options. Restore backed-up integration edits independently. Leave personal config and changed files intact. Do not commit, push, publish or send machine information remotely as part of installation.

Use the README's command/configuration reference. CLI profile/direct-directory checks bypass discovery when appropriate; removed profiles' live sessions are still accessible.
